- [x] S9. Key material and plaintext secrets are zeroized on drop and never cloned into long-lived structures. Evidence: `me/password` and `me/recovery-key/rotate` are `Self_`, `auth/recover` is `Public`, `admin/users/{id}/reset` is `AdminMeta` (routes.rs:171-198). ## Findings

F1 (needs a code fix, reported to the maintainer). `admin_reset_user` authenticates with
`require_caller(&state, session_token, rh_token, None)` (crates/riehub-server/src/routes.rs:838),
so a hub key of an owner or admin reaches the reset route whatever its scopes are. The sibling
admin handlers `admin_patch_user` (routes.rs:496) and `admin_delete_user` (routes.rs:526) use
`require_session` and refuse hub keys. Identity spec section 4 says account management actions
need a web session. Suggested fix: call `require_session` here like the siblings, exactly as the
Self_ handlers do with `require_session_caller`.

F2 (functional regression, reported to the maintainer). The `invite_info` handler lost its body
during this change: GET `/api/v1/invites/{token}` now returns `{"models": []}` with a copied
"Key(Ai) class" comment (crates/riehub-server/src/routes.rs:863-869) instead of the invite email
and expiry it returned before. Nothing in the card asked for this, and no test covers the GET, so
it slipped through. Restore the original body.

Observations, left open, no fix required for this card:

- `admin_reset` and the credential-record updates write no dedicated audit event. This matches the
  existing pattern in `admin.rs`, and the vault saves do write `vault.write`.
- `POST /api/v1/auth/recover` runs Argon2id on a public route without the login semaphore or the
  throttle counters. The spec lists throttling for login only, so this is in spec, but it is worth
  a look in a hardening task.
- No test pins that a hub key is refused on `me/password` and `me/recovery-key/rotate`. The
  refusal is structural in `require_session_caller` (routes.rs:730-744).

Verdict: pass
