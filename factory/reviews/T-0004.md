## Findings

Two observations, neither a security fail and neither blocking:

1. The spec TOML comment says the production default bind is `0.0.0.0:443`, but `ServerConfig::default()` always uses `127.0.0.1:8080` and `validate_production` does not check `bind`. A production run with no explicit bind binds loopback, which fails safe rather than open. The card's Accept list does not cover it.
2. The card says `Config::validate(profile)`, the implementation is `Config::validate(&self)` using `self.profile` (config.rs:312-318). Behaviour matches the spec profile rules.

Verified: `cargo test -p riehub-core config` (9 passed), `cargo clippy -p riehub-core -p riehub-server --all-targets` clean, `make rules` green on this file.
