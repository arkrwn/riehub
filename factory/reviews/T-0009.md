## Findings

One observation, no code fix needed. The harness deletes nothing on
drop, so each run leaves a `riehub-e2e-<nanos>` directory in the
system temp dir containing the sqlite database and the planted canary
file. The canary is a fresh random marker each run and never a real
credential, so this is a hygiene issue, not a leak of real data. A
later cleanup task may want `TestServer::drop` to remove the temp dir
after the scan.
