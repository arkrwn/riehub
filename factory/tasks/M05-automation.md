# M05 Skills, chats and workflows - version 0.5.0

Each user gets a private library, a chat workspace and YAML workflows.

## T-0501 Library: skills, instructions and agent profiles
- Version: 0.5.0
- Depends: T-0407
- Review: security
- Spec: docs/spec/automation.md section 1
- Paths: crates/riehub-automation/, crates/riehub-server/

### Build
1. New crate `riehub-automation`. Skill record (user-owned, encrypted:
   front matter, body, files). Name lookup is the keyed hash.
2. Validation as specified. For YAML use `saphyr`, or `yaml-rust2` if
   `saphyr` fails `cargo deny check`. Both are pure Rust. Record the
   pick and the reason in a new ADR. Do not use `serde_yaml`, it is
   unmaintained.
3. Import and export as `.tar.gz` with the extraction rules of the
   spec, streamed with size counting.
4. Instruction and agent profile records.
5. Routes `skills`, `instructions`, `profiles` (Self).
6. Built-in tools `skill_load` and `skill_file` for the router's tool
   stage.

### Accept
- `skill_round_trips_through_export_and_import`.
- `archive_with_absolute_path_or_dotdot_or_link_is_rejected`.
- `archive_over_limit_is_rejected_without_writing`.
- `invalid_front_matter_is_rejected`.
- `skill_body_is_not_in_db_plain` (canary).
- `other_user_cannot_read_skill`.
- `skill_load_returns_body_only_for_enabled_skills`.

### Proof
`cargo test -p riehub-automation library`

## T-0502 Chats

- Depends: T-0501
- Review: security
- Spec: docs/spec/automation.md section 2
- Paths: crates/riehub-automation/src/chat/, crates/riehub-server/

   with `sort`.

## T-0503 Web: chat workspace
- Version: 0.5.0
- Depends: T-0502, T-0408
- Review: security
- Spec: docs/spec/web.md, docs/spec/automation.md section 2
- Paths: web/

### Build
1. Chat area: list, conversation view with streaming, model and
   profile picker, tool approval cards, stop button, copy, delete.
2. Markdown rendering with `markdown-it` configured with
   `html: false` and `linkify: false`, added with a new ADR as ADR 0011

  run).

`make web-test && make e2e`

## T-0505 Workflow engine
- Version: 0.5.0
- Depends: T-0504, T-0502
- Review: security
- Spec: docs/spec/automation.md sections 3.1-3.2
- Paths: crates/riehub-automation/src/workflow/, crates/riehub-server/

### Build
1. Workflow record (user-owned, encrypted YAML, name lookup hash).
   Routes `workflows` (Self) with validate-on-save, and `runs` (Self):
   start, get, list, cancel, approve.
2. Run state machine as specified. State and counters in `meta`,
   inputs and outputs encrypted. Each step transition is saved, so a
   run survives a restart and resumes from the last finished step.
3. Step kinds `prompt`, `tool`, `approval`, `foreach`, `workflow`,
   `set`, with `if`, `timeout`, `on_error`.
4. Limits enforced: `max_steps`, `max_duration`, `max_cost`.
5. Runs execute with the vault of whoever started them (session or
   `manage` key). Audit variants `RunStart`, `RunEnd { state }`.

### Accept
- `spec_example_runs_end_to_end_against_mocks`.
- `if_false_skips_step`, `foreach_iterates_in_order`,
  `on_error_continue_continues`.
- `approval_pauses_then_resumes`, `refusal_sets_approved_false`.
- `max_steps_stops_run`, `max_duration_times_out`, `max_cost_stops_run`.
- `run_resumes_after_restart`.
- `run_data_is_encrypted_at_rest` (canary in an input).
- `nested_workflow_depth_over_3_is_refused`.
- `workflow_of_other_user_cannot_be_started`.

### Proof
`cargo test -p riehub-automation workflow::engine`

## T-0506 Triggers and standing grants
- Version: 0.5.0
- Depends: T-0505
- Review: security
- Spec: docs/spec/automation.md section 3.3, docs/adr/0013-standing-grants.md
- Paths: crates/riehub-automation/src/trigger/, crates/riehub-vault/, crates/riehub-server/

### Build
1. Standing grants: routes `grants` (Self, session only). Creating
   one adds slot `sg.<ID>` with a random key stored in the instance
   coffer at `grant/<ID>`, with an ACL of exactly the connections and
   connectors the workflow names.
2. A grant is removed when revoked, when the workflow is deleted, or
   when its tool or model set changes.
3. Scheduler: cron parsing with a maintained crate, time zones, a
   store lease per tick so one node fires. Missed ticks while down are
   skipped, not replayed.
4. Webhook trigger `POST /hooks/{wf_id}` (class `Hook`): signature as
   specified, 5 minute window, replay cache in store counters, body
   limit 1 MiB.
5. Audit variants `GrantCreate`, `GrantUse`, `GrantRevoke`.

### Accept
- `schedule_without_grant_does_not_run_and_reports_why`.
- `scheduled_run_with_grant_succeeds_without_any_session`.
- `grant_acl_excludes_other_connections`.
- `grant_is_removed_when_workflow_tools_change`.
- `two_schedulers_fire_once`.
- `webhook_bad_signature_is_401`, `webhook_replay_is_refused`,
  `webhook_old_timestamp_is_refused`.
- `grant_cannot_be_created_with_a_hub_key`.
- `revoked_grant_slot_no_longer_unlocks`.

### Proof
`cargo test -p riehub-automation trigger && cargo test -p riehub-server hooks`
